# DATA SAFETY｜資料與權限安全規範

## 禁止事項

- 不把 `.env`、密碼、Private Key、Supabase Service Role Key、正式資料匯出檔提交到 GitHub 或 ZIP。
- 不在未核准下刪除／重設正式資料，或直接對正式 Supabase 執行破壞性 SQL。
- 不宣稱網站 ZIP 可以還原資料庫；它只保存程式和發佈文件。

## 資料庫更動前的必要確認

- [ ] 已確認正式與測試環境分離。
- [ ] 已確認資料備份方式，必要時測試備份可還原。
- [ ] SQL 已先在測試資料庫完成驗證。
- [ ] 已檢查 RLS、索引、約束、舊功能相容性及資料同步。
- [ ] 已列出可能無法直接 rollback 的變更。
- [ ] 使用者已明確核准正式資料庫更新。
- [ ] 已記錄實際執行者、日期、遷移版本與驗證結果。

## 遷移檔命名（新增資料庫時）

建議 `database/migrations/YYYYMMDDHHMM_description.sql`，採由小到大的時間戳和描述。實際依專案既有工具與遷移歷史調整。

## 事故處理

1. 暫停部署及進一步寫入，先確認影響範圍。
2. 保存 Logs、Commit SHA、資料庫遷移版本與錯誤資訊（不貼機密）。
3. 確認復原對象是**程式碼、資料庫結構還是資料內容**。
4. 程式碼可回到相容版本；資料庫內容依實際備份與核准的復原程序處理。
5. 復原後重新測試關鍵路徑並記錄根因。
